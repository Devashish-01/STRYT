## Observed Patterns

- **Naming style:** snake_case throughout
- **Naming format:** object_action, past tense (`request_created`, `delivery_picked_up`). Uniform across all three domains.
- **Centralization:** single wrapper. One `track(name, props)` function, typed by an `EventName` union that mirrors a DB CHECK whitelist. Adding an event takes a migration plus a type change.
- **Error handling:** present. Both `track()` and `send()` are wrapped in try/catch. Failures are dropped with no retry.
- **Blocking calls:** no. `track()` is synchronous and fires a `void` promise. Callers never await it.
- **Placement:** 25 of 28 call sites sit in the service layer, right after the RPC or insert succeeds. Three sit in screens.
- **Privacy:** props pass through `scrubValue` (shared with Sentry and `client_errors`), and the DB caps them at 2 KB. Observed props are categorical: enums, booleans, counts and a 1–5 rating.
- **Guest support:** anonymous inserts are allowed by the `events_insert_guest` RLS policy (user_id must be null).
- **Read access:** admin-only via RLS. The only `events` reference in `src/` is the insert.

## Hygiene Notes

*Factual observations, not recommendations.*

1. `proposal_accepted` fires from `acceptProposal` only. Accepting through a counter-offer (`acceptProposalCounter`, `requestService.ts:468`) produces no event.
2. The migration comment for `booking_created` reads "an appointment or queue join". In code it fires only from `appointmentService.create`, and the queue-join path (`joinQueue`, `BusinessDetail.tsx:609`) has no track call.
3. `deal_completed` fires only for request agreements (`completeAgreement`). Completed appointments are not tracked under that name; only the delivery path is, as `delivery_delivered`. No event marks a queue token being served.
4. `delivery_started` comes from a ternary fallback, so it fires for both `LEAVING` and `ON_THE_WAY` live statuses with no property telling them apart.
5. Delivery events sent through the `riderQueue` offline outbox fire when the outbox flushes successfully, not when the rider taps the button. `created_at` reflects send time.
6. No event carries a business, provider, request, agreement or appointment identifier, so events cannot be joined back to entities or attributed to the supply-side group.
7. `marketplace_health()` is defined and typed but has no caller in app code.
8. `share_link_opened` has one call site, always with `kind: "tracking"`.
9. `otp_failed` has different property shapes per step: `bridge` and `session` omit `provider` and `native`.
10. Vercel Analytics page views live in Vercel, and product events live in Supabase. They share no identifier.
11. Group hierarchy note for design: the entity model is flat (business / provider). The current sink is a plain Postgres table, so group context would be ordinary columns or props. Of hosted tools, Segment, Mixpanel and PostHog support multi-level groups natively, while Amplitude needs workarounds.
