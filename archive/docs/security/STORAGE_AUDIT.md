## 2. Storage Object RLS Policies (`storage.objects`)

RLS is enabled on `storage.objects`. Below is the complete catalog of active policies:

### Bucket: `uploads`

1. **`User scoped insert`** (`cmd: INSERT`, `roles: {public}`)
   - **With Check**:
     ```sql
     (bucket_id = 'uploads'::text) 
       AND (auth.role() = 'authenticated'::text) 
       AND ((storage.foldername(name))[1] = (auth.uid())::text)
     ```
   - **Enforcement**: Prevents unauthenticated uploads. Strictly restricts the top-level path segment to the caller's own Supabase Auth UID. No user can write files into another user's prefix.

2. **`User scoped update`** (`cmd: UPDATE`, `roles: {public}`)
   - **Qual**:
     ```sql
     (bucket_id = 'uploads'::text) 
       AND (auth.role() = 'authenticated'::text) 
       AND ((storage.foldername(name))[1] = (auth.uid())::text)
     ```
   - **Enforcement**: Users can only overwrite/update objects within their own UID folder.

3. **`User scoped delete`** (`cmd: DELETE`, `roles: {public}`)
   - **Qual**:
     ```sql
     (bucket_id = 'uploads'::text) 
       AND (auth.role() = 'authenticated'::text) 
       AND ((storage.foldername(name))[1] = (auth.uid())::text)
     ```
   - **Enforcement**: Users can only delete objects within their own UID folder. Strangers and attackers cannot delete other users' avatars, catalog items, or portfolio images.

4. **Public Read**:
   - Because `public = true` on `uploads`, `GET /storage/v1/object/public/uploads/...` is served directly by Supabase Storage without checking RLS, enabling CDN caching and fast media rendering.

---

### Bucket: `verification-docs` (KYC / Identity Documents)

1. **`verification_docs_owner_insert`** (`cmd: INSERT`, `roles: {public}`)
   - **With Check**:
     ```sql
     (bucket_id = 'verification-docs'::text) 
       AND (auth.role() = 'authenticated'::text) 
       AND ((storage.foldername(name))[1] = (auth.uid())::text)
     ```
   - **Enforcement**: Users can only upload KYC documents into a folder named with their own UID (`verification-docs/<uid>/...`).

2. **Read / SELECT Security**:
   - **Bucket `public` setting**: `false`. Direct URL access (`/object/public/...`) returns HTTP 400/404.
   - **RLS SELECT policies**: **0 policies exist for `{public}` or `{authenticated}`**.
   - **Result**: Direct reads via PostgREST or Storage API are completely blocked for all client actors (anonymous and authenticated).
   - **Authorized Access Path**: Documents are retrieved exclusively by verified human administrators via the `verification-review` Edge Function (`supabase/functions/verification-review/index.ts`), which runs with secret key privileges and issues short-lived 300-second signed URLs (`createSignedUrl(path, 300)`).

---

### Bucket: `app-updates` (OTA Bundles)

1. **Write Protection**:
   - **RLS policies**: **0 INSERT, UPDATE, or DELETE policies exist for client roles**.
   - **Result**: Only `service_role` / backend publish scripts (`scripts/publish-ota-update.mjs`) possessing secret credentials can upload or mutate files in `app-updates`. No client or malicious actor can replace update packages.

2. **Read Access**:
   - **Bucket `public` setting**: `true`. Public read allows the Capacitor native app shell to download zip archives. The version manifest `latest.json` is served via the `app-update` Edge Function to prevent CDN caching issues and support `MIN_NATIVE_VERSION` gating.

## 3. Path Traversal & Integrity Assessment

- **Path Separation**: The application uses `(storage.foldername(name))[1] = auth.uid()::text` to enforce physical folder boundaries in PostgreSQL.
- **Client Path Generation**: In `src/services/core/uploadService.ts`, upload paths are generated as:
  ```ts
  const randomPath = (uid: string, kind: string, ext: string) =>
    `${uid}/${kind}/${Date.now()}-${Math.random().toString(36).substring(2, 9)}.${ext}`;
  ```
- **Directory Traversal**: Because PostgreSQL storage policy checks the parsed `storage.foldername(name)[1]`, path traversal attacks (e.g. `../`) are rejected by PostgreSQL regex/path normalization.
