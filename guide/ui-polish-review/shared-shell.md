# Shared shell and design system review

Scope: `src/App.tsx`, `src/components/BottomNav.tsx`, `src/components/DesktopSidebar.tsx`, `src/components/RouteFallback.tsx`, `src/index.css`, and app entry metadata. This is a code review, not a device or user study. No application code was changed.

## Findings

| ID | Priority | Verified finding | Evidence | Proposed change | Status |

| S1 | High | The mobile Create sheet is rendered as ordinary `div` elements. It has no dialog name or modal semantics, no focus move or containment, no Escape handling, and no focus return to Create. Keyboard and assistive technology users can continue into the page underneath. | `src/components/BottomNav.tsx:77-161` | Use the shared dialog/sheet primitive or add `role="dialog"`, `aria-modal`, labelled heading, initial focus, Escape and focus restoration. ## Cross-screen acceptance criteria

1. Every routed screen has one clear heading, a descriptive document title, and an intentional keyboard focus destination after navigation.
2. Shared sheets handle pointer, keyboard Escape, native Back, focus containment and focus restoration consistently.
3. Navigation highlights the actual destination on mobile and desktop, including query-based tabs.
4. Primary actions, status labels and key metadata remain readable at narrow widths and increased text size; hit targets remain at least 44 CSS pixels where practical.
5. Loading, empty, error and success states use the same visual language and preserve a clear next action.

## Review boundary

The findings above are verified from code. Visual quality, contrast and device-specific safe-area behavior still need screenshot and device validation during implementation. Competitor names are used as a quality benchmark, not as a source of copied UI.
